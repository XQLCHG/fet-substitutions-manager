# 智能监考排班系统

本分支在原 `fet-substitutions-manager` 基础上新增面向国内高校/学校的独立监考排班工作台。

## 入口

本地启动原项目后访问：

```text
http://localhost:8080/invigilation
```

开发模式访问：

```text
http://localhost:5173/invigilation
```

使用原项目管理员账号登录。

## 支持的岗位

默认内置四类岗位，并允许后续继续新增岗位：

| 代码 | 名称 | 默认作用范围 | 默认工作量权重 |
|---|---|---|---:|
| PRIMARY | 甲监 | 考场 ROOM | 1.2 |
| SECONDARY | 乙监 | 考场 ROOM | 1.0 |
| ROVING | 流动监考 | 楼层 FLOOR | 1.1 |
| INSPECTOR | 巡考 | 考区 AREA | 1.3 |

地点使用层级模型：校区 → 考区 → 楼栋 → 楼层 → 考场。

## 推荐使用流程

1. 进入“考试数据”，创建考试批次。
2. 下载“监考人员模板.xlsx”，填写人员、岗位资格、场次上限和不可用时间后导入。
3. 下载“考试安排模板.xlsx”，填写日期、时段、课程、地点和各类监考需求后导入。
4. 进入“自动排班”，先点“检查能否排开”。
5. 若没有硬约束缺口，点“一键自动排班”。
6. 对已经确认/通知的安排点击锁定。
7. 人员临时变动时删除或修改相关安排，再次一键排班；锁定项保持不变，其余项局部优化。
8. 导出 Excel 或打印版 PDF。

## 自动排班约束

### 硬约束

- 每个地点、时段、岗位人数必须精确满足。
- 同一人员同一时段最多承担一个岗位。
- 人员必须具备对应岗位资格。
- 整日/指定时段不可用人员不得安排。
- 每日最大场次和总场次上限必须满足。
- 默认情况下，任课教师回避自己课程所在考场的甲监/乙监。
- 已锁定分配必须保持。

### 软约束

- 按岗位工作量权重平衡人员负载。
- 尽量避免连续时段监考。
- 局部重排时尽量保留原有未锁定安排，减少通知变化。

## 不可行诊断

在调用 CP-SAT 前会先检查常见硬约束缺口，包括：

- 某个岗位合格/可用人员少于需求。
- 某一考试时段总岗位数大于可用不同人员数。
- 锁定人员已不符合资格或不可用。
- 锁定人数超过岗位需求。
- 岗位作用范围与地点类型不匹配。

系统会在前端显示具体日期、时段、地点、岗位、需要人数和候选人数。

## 数据与兼容性

新增数据继续保存在原项目每个机构自己的 `gestor.db` 中，表名使用 `invigilation_*` 前缀。原 `vigilancies`、`substitucions` 等表不被迁移或重写，因此旧功能可以继续使用。

## 验证

仓库新增 `.github/workflows/invigilation-ci.yml`：

- Python `compileall`
- 监考数据约束回归测试
- CP-SAT 求解器回归测试
- Vue production build

正式投入真实考试前，仍应使用学校实际规则和脱敏历史数据做一轮验收测试，特别确认甲监/乙监资格、流动监考范围、巡考范围、每日场次上限及任课教师回避规则。
